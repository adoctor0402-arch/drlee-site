## 流程

### 1. 先同步

```
cd ~/Documents/Claude/茂盛小王子網站/drlee-site
git pull
```

GitHub Action 每週一台灣時間 08:00 會抓 PubMed 新論文，commit 進 `content/observatory/`。
那些檔案的標題是英文原文，takeaways 是「（待補）」，這是刻意的，不是壞掉。

`git log --oneline -5` 看有沒有 `observatory-bot` 的新 commit。沒有新論文就停在這裡，
跟李醫師說這週沒有新的就好，不要為了有產出去硬找。

### 2. 逐篇查核

這是整個流程裡唯一重要的一步。每一篇都要回原始論文核對，不能只看摘要就寫。

查核的時候用 Agent 平行跑，一篇一個，給它 DOI 和要驗證的每一條主張，
要它逐條回報 CONFIRMED／WRONG／UNVERIFIABLE。

**今天踩過的雷，一定要避開：**

- **分清楚摘要和全文。** 讀不到全文就明講「全文在付費牆後，以上取自摘要」，
  不要寫「作者承認⋯⋯」這種你無法證實的話。
- **新聞稿不是論文。** 新聞稿常有論文裡沒有的數字。只出現在新聞稿的東西要標明出處，
  不要寫進 takeaways 當成論文的內容。
- **二手科普網站不能當來源。** 連摘要都讀不到的論文，建議不上，不要用二手報導拼出一篇。
- **不要自己補數字。** 摘要沒給效應量就寫「摘要未提供效應量」，不要生一個出來。
- **利益衝突要查。** 業界出資、作者是公司員工、檢體來自自家產品，這些都要寫出來。
- **內部驗證不是外部驗證。** 同一批資料隨機切分出來的驗證組，不可以寫成「獨立驗證」。
- **病例對照研究的 AUC 不能當篩檢效能讀。** 病例比例被人為墊高的資料集算出來的數字，
  給不出陽性預測值。
- **關聯不要寫成因果。** 論文自己用因果字眼的時候，中文要比論文更保守，不是跟著加強。

被擋的網域（不要用 curl 或 python 繞過去，繞不過，而且不該繞）：
`nature.com`、`jamanetwork.com`、`fertstert.org`、`pubmed.ncbi.nlm.nih.gov`、NCBI eutils。
`link.springer.com`、`academic.oup.com`、`api.crossref.org`、`api.openalex.org` 通常可讀。
Crossref 的 API 會有出版社自己存的摘要，付費牆論文可以從那裡拿到逐字摘要。

### 3. 改寫

體例固定成兩節，不要用舊的三段式：

```
## 小王子醫師說

（三百到七百字，口語，像在門診講話。先講這篇在臨床上代表什麼，
再講哪些人適用、哪些人先別急著套用。保留的地方要具體說是哪裡保留。）

## 延伸閱讀

- [原始論文：期刊名](DOI 連結)
```

frontmatter 的 `takeaways` 是「三十秒看懂」那一欄，寫研究設計、樣本數、主要結果，
帶效應量與信賴區間，有分母要寫分母，最後一條寫限制。

`draft: true` 不要動。上架是李醫師按過之後的事。

### 4. 丟上審稿頁

手機審稿頁是一個 Artifact，資料存在它的 `verdicts` collection（用 ArtifactData 讀寫）。
那一頁只放還沒上架的，已經上架的不要再放上去，李醫師明講過不要再讓他重看。

做法：用 Artifact 的 read 讀回現在的 HTML，把新的幾篇做成 `<article class="item">` 卡片
加在 `<div id="list">` 後面，重新編號、更新 `var ITEMS` 與「X / Y 已決定」，再 publish 回同一個 url。

卡片內容：`小王子醫師說` 的段落放 `.say`，frontmatter 的 takeaways 放「三十秒看懂」的
`<details>`，`.src` 連到原始論文。

### 5. 通知他

跟他說這週有幾篇、每篇一句話是什麼、查核時發現了什麼問題。
發現自己之前寫錯的要主動講，不要默默改掉。

## 不准做的事

- **不要 push，不要部署。** commit 可以，push 和 `npx vercel --prod` 由李醫師自己在他的
  Terminal 執行。不要代他輸入 GitHub 帳密。
- **不要替他上架。** 把 `draft` 改成 `false` 之前一定要有他的通過。
- **不要用他的名義對外發言。** Threads、粉專的貼文可以寫草稿，但送出鍵他自己按。
- **不要把私人事務寫進公開頁面。** 板橋分院財務、醫療社團法人、日本買房、養生村評估、
  韓式咖啡館、幹話日曆，這些都不要出現在網站上。

## 兩個容易出事的技術細節

- **`device_commit_files` 回報成功不代表寫對了。** 寫完一定要在 Mac 上核對內容，
  曾經發生過它回報 written 但檔案是舊版的情況，那次差點把整個實驗室頁下架。
- **git 在掛載資料夾裡會留下 `.lock` 檔。** commit 完要清掉，不然李醫師下次跑 git 會卡住。
  需要刪除權限的話用 `device_request_delete_permission` 要。
